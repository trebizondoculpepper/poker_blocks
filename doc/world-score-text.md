Preserve the shared fitted rectangular multiline style and the captured hand/base/modifier/final content from [scoring explanation](scoring-explanation.md). ## Reusable text renderer, separate anchor

Extend the shared measured text layout with a graphical rendering adapter: draw its returned lines, font sizes, measured spacing and style into an owned canvas texture on an unlit transparent quad. Reuse layout/measurement/cache invalidation; do not create a second wrapping/fitting algorithm or use visible DOM text as the graphical output. Canvas is a texture source, not a screen-positioned HTML caption. The quad is a presentation object rendered through the existing host/camera. No WebGL renderer per label.

The renderer consumes captured text/style, a rectangle budget and a visual anchor binding. It knows no poker hand, passive, material or scene identity. Registered row placement supplies world position/orientation/size; passive activation retains its own over-item placement and may reuse this renderer later through an explicit adopter. This request does not silently move passive labels or discard their current accessible announcements.

## Row association and reversible audition defaults

Bind to the captured ordered row's opaque visual handles and endpoints. Resolve their current presentation transforms through mount capabilities, not live GameRun cards or rescoring. The annotation anchor is the row's visual midpoint with a small configured camera-facing offset so the text reads over the row rather than on a block face. Its world-space width derives from the row's visual span with a bounded minimum/maximum; it moves with the structure and responds to gameplay zoom. It is not pinned to a fixed screen location.

For the first implementation choose a camera-facing quad, with its text baseline aligned to the row's projected direction and flipped when necessary to keep letters upright. A row viewed end-on uses camera horizontal as the deterministic fallback; never normalize a zero-length projection. Avoid mirroring glyphs during rotation. This makes association visible without requiring the player to read text edge-on along a world axis. Exact orientation/offset/size are configured presentation tuning, not gameplay rules.

Render annotations as an explicit host contribution after world geometry, using the same board camera. Initial readability policy is annotation-only depth independence: world objects do not hide the text; labels still have world anchors/scale, not DOM positions. Preserve renderer state and ordinary geometry depth; do not globally disable depth. Stable captured order and a registered placement policy add small row-local offsets for overlapping annotations rather than moving them to an unrelated HUD corner. Off-screen/fully missing anchors omit the visual with a bounded diagnostic and retain accessible full text, never invent a new gameplay target. Browser audition must check whether this policy reads well; physical occlusion or fully world-oriented glyph planes are later alternatives, not claims of current behavior.

## Motion, timing and lifetime

Keep the existing scheduled line start and duration; do not add a queue, extra narration delay or outcome gate. One finite effect on the shared presentation clock owns growth/fade and exposes completion/cancellation. Initial designer tuning: scale 1.00 to 1.06 over its duration, with opacity held then faded over the final quarter. Configuration uses normalized progress and game-time duration, never a private wall-clock deadline. Reduced motion keeps scale 1 and uses a static/brief soft-fade cue through the same bounded lifetime.

The host owns shared quad geometry and registered render contributions; each label owns its texture/material lease and anchor subscription. Cache by captured text/style revision/resolution budget, with reference-counted release; font readiness invalidates the affected texture generation without a retry timer. Bound active labels and texture dimensions through the existing presentation admission/configuration limits, report actual resource counts and use the established overload summary/accessible path rather than allocating without limit. Disposal/cancel/reset/scene exit releases once; a late font/anchor update cannot resurrect a disposed label. Source replacement rebinds only compatible current visual mounts under the captured identity; removed rows end safely. No shared material mutation, session RNG, model commands or input busy lock.

Keep the one polite live-region announcement of full captured text. Graphical glyphs are decorative to assistive technology and must not announce again on every move, growth or font rebuild. Do not leave a duplicate visible HTML caption behind the new renderer.
