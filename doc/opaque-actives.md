# Opaque rankless actives and replacement (#552)

Target reusable contract after [ordered ownership](ordered-card-ownership.md) (#550), [Presents](presents.md), [game events](game-events.md) and exact clone/reset contracts (#580). Evidence: `cards.ts` constructs ordinary ranked cards; `card-material.ts` rematerializes existing instances; `card-ownership.ts` distinguishes deck/field ownership; `save.ts` reconstructs cards from IDs and validates material/state adapters. These are foundations, not proof a rankless wrapped object already works. Present artwork currently previewing an ordinary card must not define production semantics.

## Capabilities, payload and identity

A playable block definition provides its registered placement, inspection, discard, scoring and optional opening capabilities. Rankless is **absence of a rank/suit value provider**, not rank zero, a fake suit, or a material test in a scorer. The public scoring contract consumes value providers only after opening and validates that the phase's required providers exist. A refusing/no-value behavior is registered where appropriate; it does not become an `isPresent` flag. Placement validation uses the same attach/placement capability as normal cards, including first play/group placement.

An opaque-container instance holds exactly one stored **unplaced playable instance descriptor** with a fresh payload ID, definition handle and validated component state. Payload ownership belongs to the container; it is not simultaneously in deck/hand/field/discard or counted as a second inventory object. The wrapper has its own ID. Definition/shared render resources are referenced, while payload mutable state is independent. Initial implementation permits a non-container playable payload; reject recursive/cyclic or aliased payload graphs, duplicate IDs and unknown codecs. Do not discover recursion safety by rendering an arbitrary nested graph.

The container's inspectable provider describes opening behavior without exposing rank, suit, material, seed, source texture or another hint about hidden contents. Shop/inventory/hover/activation labels consume that public provider, not raw serialized payloads. Internal save data necessarily contains the payload and is not a cryptographic secret. No sale capability is composed onto Present. Discard uses `discardable`, preserves wrapper/payload and returns at the ordinary round boundary. Nothingifier/removal consumes the owned subtree once through the existing removal/ownership command; it does not reveal or independently adopt the payload.

## Creation and generation

At the configured reward boundary generate the payload once with the existing seeded RNG and shared card generator, then adopt the wrapper into the run deck. Generation plus ID allocation plus reward receipt are one transaction; rollback restores all three. The generator accepts explicit registered distribution/provider references and a progression context. The Present configuration selects **the next configured round's shop playable-card distribution**, or the last configured table when no successor exists. This successor/clamp is a registered progression query, not a literal round-eight branch. Copy the shop distribution's rank/suit/material policy; exclude ineligible payload providers via their configured eligibility, including Paper, another opaque wrapper and experimental-only entries. Filter/renormalize weights deterministically; an empty eligible pool is an explicit configuration failure, not Paper fallback.

The wrapper has no reroll recipe executed on opening. Repeated saves, clones and delayed placement preserve the chosen descriptor. Duplicate rank/suit with another live card is allowed; IDs remain distinct. Present acquisition is the already agreed stage-three completion reward, not a shop offer. No prices or stocking rules are introduced here.

## Atomic opening/adoption

The registered opening command validates the wrapper owns its payload, its current cell/zone and the payload's capabilities. It removes the wrapper from ownership, promotes the payload from container ownership into the **same field cell**, adds its run-owned provenance/codec record, and emits `block.opened` with immutable wrapper and payload snapshots plus replacement IDs. There is no instant at which both are field members and no second synthetic placement. Failure preserves wrapper/payload/field/RNG. Opening uses zero generation RNG.

For a batch, resolve each wrapper independently in captured placement order; finish all openings before pre-score material reactions, then score and post-score material actions under `game-events.md`. The revealed card participates in the current play and its normal placement-timed material behavior; return it to the run deck under ordinary ownership later. A removed wrapper's ID must not reappear in future draws/Continue. Visual mounts use the captured replacement relation to show the wrapper for five game-time units and transition to the payload, then subsequent effects; model completion/input never wait for that animation. `block.opened` is not destruction or discard.

## Persistence and clone compatibility

Keep the current save envelope version for backward-compatible **optional fields** only where the existing decoder can be extended without changing existing records. Add optional `state.activeObjects`, a dictionary from instance ID to `{ definition: string, components: Record<string, unknown> }`, for run-owned instances not reconstructible from the ordinary deck/card ledgers. Registered component codecs own validation/copy/restore. The opaque-payload codec stores its one nested `{ id, definition, components }` descriptor; that nested object is not also a top-level live record. Preserve the existing ordinary-card ledgers during this additive migration rather than duplicating the same instance across both stores. Existing zone ID arrays reference the wrapper while unopened and the revealed payload afterward. Extend the existing generated/bought provenance decoding through registered instance codecs; do not force rankless data through `standardDeck` indexing or infer a type from ID spelling. An old record lacking the extension decodes exactly as before. Unknown codecs, invalid nested state, duplicate IDs, cycle/depth violations or missing/extraneous zone references reject the save. If implementation finds the proposed extension incompatible with the actual current schema, return the concrete conflict for a separately documented schema version before code; do not silently weaken validation or fabricate a migration.

Adopted revealed payloads serialize as run-owned playable instances with their current material/state/modifiers. Unopened payloads remain nested and hidden in public inspection. Exact cloning allocates fresh wrapper and payload IDs while preserving all content/state; it must not alias an original payload or reroll it. Reset-clone delegates only to configured reset behavior; an opaque container can explicitly preserve its stored payload rather than regenerate. These operations return unplaced instances, and only the calling command adopts them into an explicit destination.
