# Ordered cards and authoritative ownership (#550)

Target contract, documentation before implementation (#551/#472/#574). Evidence: `deal.ts:drawCards` currently splices a new random index per draw; `dealer.ts:refillHand` delegates to it. `card-ownership.ts:cardOwners/clearField/removeCardForRun` has registered ownership return/removal but uses reconstruction ledgers. `save.ts` stores ordered zone IDs and reconstructs the starting/bought/generated cards; `game-run.ts:clearTable/leaveShop` coordinates stage/round cleanup. The [lifecycle audit](research/gameplay-lifecycle-opportunities.md), [game events](game-events.md) and [Presents](presents.md) establish identity, transaction, RNG and reward constraints. These observations do not establish the target has shipped.

## Ordered zone capabilities

Deck and hand own only their ordered contents. The next deck element is **index zero**. Registered `pop` removes that same logical card from the front without RNG. Empty pop returns an explicit empty result with no mutation. Batch draw validates availability/count before any move and either transfers the entire requested set or rejects, unless the calling registered deal policy explicitly requests up-to-available. `shuffle` is an unbiased Fisher–Yates permutation using the run's seeded RNG, operating on existing identities without cloning cards. A deck operation never chooses dealer policy or creates inventory entries.

Registered zone-transfer commands own the atomic remove/adopt of instances and emit captured lifecycle facts. A hand drag source and a field drop target invoke those commands through the gameplay coordinator; generic controllers contain no material/active cases. An owner may permit a card to exist in the field without joining the run deck (temporary generated cards). The ownership capability determines return location; retention determines expiry. Neither duplicates the other's decision.

Shuffle at initial deck setup and after collecting eligible run-owned cards for a new stage; stage end alone does not prematurely move discarded cards. Preserve the **round-long discard exclusion**: discarded cards stay in discard across stage one/two and return only at the configured round boundary. Purchases/grants join the run-owned deck; where the configured acquisition contract requests a shuffle, shuffle once after the batch, not once per inserted card. Present stage-three grants enter before the next round shuffle. No draw rerolls or skips a card based on its material. Existing random-index draw is explicitly retired by #551 after this contract merges.

## Run inventory is a query

The run exposes a pure inventory trait/query over current authoritative **deck, hand, field and discard** snapshots. It returns immutable records with instance ID, card capabilities/current rank-suit where applicable, material/state/modifiers, ownership and location/order or cell. Do not treat payloads, starting-deck definitions, bought-card history or removal receipts as another live zone. Each owned live instance appears exactly once; temporary field cards are shown while present, marked with their retention. A removed instance appears nowhere, including inventory. Rank/suit duplicates are valid separate IDs; a grid can stack/list duplicates and show rankless actives separately rather than invent a suit/rank.

The inventory screen (#472), accessible from game and shop through configured navigation, renders this query with existing material visuals and location descriptions. It owns no second mutable catalog and cannot move a card by changing a display record. A later query sees committed changes; an earlier event's inventory snapshot never changes retroactively. Clearing a removed card's historic instance state is cleanup, not an implicit reset or rediscovery from its original definition.

## Discardable capability (#574)

A `discardable` behavior exposes a registered validation/command contribution for the requested card and action context. Per-card eligibility is separate from dealer allowance and multi-selection policy. Ordinary cards and unopened rankless containers compose the same capability. An explicitly refusing behavior returns a reason, not a marker flag another owner checks. Input sources/targets call the capability; no adapter branches on card kind or checks trait presence as permission.

Validate the complete selected group and remaining allowance first. Success moves those same instances from hand into discard in their original selected hand order, commits allowance/refill/RNG atomically, and emits one action summary plus ordered per-card discard facts. Failure leaves zones, RNG, uses and allowance unchanged. Discarding an unopened container preserves its hidden payload and does not open it. New hand draws use ordered pop. Restore reinstates the saved discard zone without re-discarding or playing its action sound.

## Boundary cleanup and lifecycle ownership

Settlement consumes the outgoing field/hand state for rewards before cleanup. At a boundary: finalize/pay once; expire configured retention through registered removal/expiry commands; request configured resets on survivors; clear matching modifier lifetimes through their existing independent handlers; return eligible zones through ownership/transfer commands; shuffle once when entering the next stage/round. Stage and round boundary handlers declare deterministic order; on a round boundary run each applicable reset/expiry once. Expiry/return/reset are not explosive destruction and do not trigger shredding or blast reward transfer. Run modifiers survive ordinary reset. Events and rollback follow `game-events.md`.

Map operations to behaviors, not controller branches: pop/shuffle (#551); validation/zone transfer and lifecycle phases (#612/#614); discardable (#574); configured retention (#504/#505); reset facet and boundary integration (#580/#506); generation/adoption/replacement (#552–#555); pure inventory/UI (#472). `GameRun` orchestrates requests and holds state; dealer supplies rules. Do not rename/rewrite unrelated controllers as part of this migration.

## Save/Continue path

For initial ordered operations the existing zone arrays already preserve order. Keep their encoding and exhaustive validation; change draw semantics, not serialized order. Legacy `removedCards` is a **historical reconstruction record**, never a live card/inventory entry. Decoding an old format may use that record to exclude original definitions; runtime queries must not enumerate it. No legacy adapter may recreate a removed card or replay rewards/actions. Starting/bought/generated metadata is not a second mutable inventory authority.

A self-contained live-card encoding, if required by rankless payload adoption, is a registered **versioned save schema** containing each current instance descriptor once and ordered zone references. The implementing save slice must document its precise schema/version before changing bytes; this contract deliberately does not prescribe an unverified migration. Existing supported records remain readable under their registered decoder; unknown/corrupt/incompatible records fail explicitly under the existing policy. Do not silently drop removed/payload state or weaken exhaustive validation to make a new card parse. This leaves #551/inventory unblocked by a speculative wholesale save rewrite; concrete payload schema is the separate #552 contract.

Verify unique live IDs/exactly one zone; order survives Continue and future draws match an uninterrupted run; no RNG on pop, correct RNG on shuffle; material/modifier state survives movement; discards do not return between stages; purchased/generated and expired cards obey ownership; removal stays absent. Multi-transfer failure must roll back both state and RNG. No game-wide save format change is authorized merely to implement ordered pop.
