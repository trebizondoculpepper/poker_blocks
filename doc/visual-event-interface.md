# Visual-event scheduler interface (#545)

Concrete target after [the scheduler architecture](game-architecture.md#visual-event-scheduler-and-game-time-units-541), TinyQueue research #557 and Tween.js research #556. These define one presentation clock and registered dispatch; this document fixes the implementable API, bounds and migration checks. Runtime remains #546 onward.

## Narrow API and records

Use opaque typed handles for generation, scope and event. A scheduler instance exposes:

- `createScope(parent, config)`: establish a scope in the current generation, with producer registration open and a registered overload/missing-target policy reference.
- `schedule(scope, {handler, payload, dueUnits, originUnits})`: atomically validate and admit an immutable description, returning `{accepted, handle}` or `{accepted:false, reason}`. Times are absolute presentation units; `originUnits` is captured action/phase start for relative clients. Due times must be finite/nonnegative. Payload codecs validate/copy/freeze plain data before admission; no meshes, game controllers, callbacks or mutable model references.
- `scheduleBatch(scope, descriptions)`: all-or-nothing admission in listed order, so a stagger cannot half-admit silently. Return rejected status without incrementing scope counts. Producers handle explicit partial legacy work via their fallback, not a hidden transactional gameplay operation.
- `seal(scope)`: producer has no more initial work. Descendants spawned by admitted handlers still register under their open handler lease before that lease settles. Calls after completion/cancellation reject; a late unrelated caller cannot reopen a completed scope.
- `cancel(handleOrScope)` and `disposeGeneration()`: idempotent ownership cleanup and exactly-once cancelled settlement.
- `update(realNowMs, visibility)`: advance the shared clock and bounded dispatcher; interpolation uses the resulting `clock.nowMs`. One host owns calling this; handlers cannot recursively update.
- `observe(scope, listener)` / `status(scope)`: immutable completion state (`pending`, `finished`, `cancelled`, `failed` plus diagnostic). Observer registration returns unsubscribe and observes an already terminal state once without re-executing work.

Exact exported TypeScript names may follow project conventions. Registry keys select handler implementations, never identities. A handler receives `{clock, scheduledAtMs, nowMs, scope, schedule, cancel, services}` and its captured payload; it returns either an immediate settlement or a bounded effect handle `{update(nowMs), cancel(), dispose()}` with a single terminal result. Asynchronous asset preparation may return a cancellable pending handle and must retain its scope lease; late resolution checks generation before mounting. No handler receives model mutation/RNG access.

## Clock and deterministic dispatch

Convert units through `units * 1000 / 15` at the clock boundary. Visible elapsed rAF time advances a monotonic clock without simulation clamping. Hidden time is excluded and the next visible real timestamp rebases the clock; interpolation does not see a discontinuity. Explicit host presentation pause behaves similarly. Gameplay pause does not automatically stop foreground menu feedback. A future speed scalar is one clock conversion concern, not an implemented setting.

Heap ordering is `(dueAtMs, insertionSequence)` using pinned `tinyqueue` 3.0.0. Pop due starts stably within the per-update budget. An overdue effect retains its **scheduled** start timestamp, so its first update may be partially/fully elapsed; its one-shot start sound dispatches once, never per missed frame. A configured producer may replace a whole saturated sequence with a summary but the scheduler does not invent such policy. Same-time nested events get later insertion numbers and share the same budget. Work scheduled from interpolation completion waits for scheduler admission/next dispatch pass, never recursively runs inside the library callback.

The Tween.js adapter receives the same explicit `nowMs`, owns one manual Group per scheduler/host, removes members on finish/stop and settles its scheduler effect exactly once. A tween completing immediately still follows that lifecycle. Finite effect timeouts below use presentation time, so hiding the tab does not falsely declare failure.

## Initial bounds and fallback

Reversible engineering defaults, configurable by the host preset: **4096 pending events globally, 1024 pending per action scope, 512 active effects globally, 128 event starts per update, descendant depth 32, 30 seconds maximum finite-effect duration**. A scope may explicitly configure a shorter limit or a separately bounded longer duration where a documented effect needs it. Global pending/active limits cannot be disabled. Validate positive integer counts/finite durations before mounting. These numbers bound references/work rather than assert frame-time or byte-memory guarantees; profile real payloads before tuning.

A start at the active cap remains due without constructing resources; pending admission still respects its own cap. Per-frame budget starvation/backlog is observable. An admitted finite effect exceeding its declared max duration is force-cancelled/disposed, recorded failed, and invokes its producer's registered summary fallback once. Unknown/incomplete payload or missing required service rejects before queue insertion. Optional-only producer policy may settle as omitted with an explicit diagnostic; required narration policy replaces it with a captured summary via a **direct bounded sink**, not another admission into a full heap. Fallback receives no gameplay mutation API. Failure of that sink settles the scope failed and exposes the captured final-state summary at the result host; it does not leave a gate waiting indefinitely.

Admission updates counts only after validation. Cancel removes pending records and payload references immediately, rebuilding TinyQueue from remaining entries (O(n), acceptable bounded initial tradeoff); no unbounded tombstone retention. Active handles cancel/dispose once even if callbacks arrive later. Descendant registration checks depth/counters before admitting; closing a rejected child cannot decrement an unrelated count. A sealed scope completes only after pending/active/descendant leases all settle. Completion diagnostics retain small immutable metadata, not meshes or full payload graphs indefinitely; observers release on scene exit.

Synthetic-load acceptance is reproducible without real sleeps: enqueue 4096 events then reject event 4097; require 32 dispatcher updates for 4096 immediately due starts at budget128; reject depth33, cap a scope at1024, exercise512 active handles, then cancel all and verify zero retained payload/heap/active references. Inject late time and verify stable scheduled starts. Measure this fixture's actual CPU/memory in the implementation PR; the arithmetic validates bounds, not runtime performance. Include partial-child rejection and fallback-failure fixtures so terminal accounting cannot hang.

## Migration order and acceptance

1. **#546 service only:** fake handler proves stable time/sequence, finite caps, nested scheduling, sealed-scope completion, async cancellation, hidden-time rebase, invalid payload/time, fallback, resource release and new generation. No production consumer switches yet.
2. **#547 scoring:** capture selected lines, operands/endpoints, activation IDs and terminal outcome once. Queue narration in committed-action order. Remove the old score-step/outcomeAt scheduler, not scoring logic. Two model-valid plays commit immediately while play1 feedback runs; play2 narration follows without reading play2 state for play1. Terminal screen requires authoritative outcome plus relevant bounded scopes.
3. **#548 flights/discards:** adapt existing effect bodies to the clock and captured target/mount contract. Layer transform channels so spring/pulse/flight do not overwrite one another. Remove replaced timing arrays/callbacks. New interaction can cancel its old motion from the displayed pose; it cannot be rejected because an animation is busy.
4. **#549 exits:** adapt `ExitEffectInstance` update/finish/dispose to bounded handles. Retain snapshot visuals after authoritative removal without resurrecting cards. Resist/return/reset/replacement follow their distinct facts. Exit cleanup releases per-instance resources and keeps shared assets alive.
5. **#542 stagger / #540 rack:** capture left-to-right activations, schedule t/t+2/t+4 units, first immediate. Pulses can overlap; completion awaits all children. No extra RNG or rule application. Source disappearance follows declared snapshot/missing-mount policy; rack changes cannot reorder an old play.

Ambient smoke, bubbles, shader clocks, grass and spring integration remain per-frame and outside completion scopes. Only their finite action-start/stop orchestration uses the queue. Do not move every particle update into scheduled events. Each migration cites its source/target ownership and provides a browser clip/input-overlap check in addition to injected-time tests. Queue records are not saved; restoration produces no historical effects/rewards/sounds.

## Capacity-model evidence

Run `python3 doc/research/scheduler-capacity-probe.py`. The probe models admission/counter arithmetic, not the production scheduler, and passed: 4 scopes × 1024 pending = 4096; next admission rejected without count change; 32 updates drain that backlog at 128 starts/update; depth 33 rejects while depth 32 admits; partial child rejection leaves only the admitted child's count, and cancellation clears modeled references. The model admits 512 active handles, refuses the 513th and retires all 512 at the injected 30-second limit; this is model accounting, not a production effect-resource test. This evidence supports finite accounting defaults; it does **not** establish CPU/GPU/memory cost or actual callback/cleanup correctness. #546 must execute the richer adapter fixtures above against TinyQueue and real handle lifecycles before claiming those results.
