# Tabbed run-status screen

Owner-approved scope #1337, documentation #1369, 2026-11-15. Replace the existing deck-view entry's content with two configured read-only tabs: **Deck** and **Gameplay Status**. This is the agreed target, not a claim the new screen has shipped.

## Deck: current cards and material inspection

Keep the existing meaning of the viewer: **all live run cards**, with their current registered location markers (draw pile, hand, table, discard, and any future registered live zone). It is not merely the remaining draw pile and not a second saved inventory. Preserve per-instance duplicates and omit permanently removed cards. The tab title can remain Deck, but heading/help must say Your cards and explain the included zones; remaining-draw count is separately labeled. Temporary/table-only cards remain distinguishable by their existing location/lifetime description and are not promised as permanent deck ownership.

Each entry shows its rank/suit or existing rankless label **and a visible current material name**, not color alone, a data attribute or hover-only material evidence. Reuse the material definition's public descriptor. Grouping/order is presentation order, not draw order: use the shared rank/suit order and deterministic identity tie ordering, never expose the underlying draw sequence or next card. Hidden Present contents stay opaque; report only the wrapper's permitted public material/weight/bonuses.

Hover, keyboard focus and tap reveal the same complete inspection descriptor: material, authored instance mass/weight and full applicable bonuses with relevant scope/lifetime/condition. Reuse `inspectBlock`, registered inspection providers and mass formatting rather than copy rules into the deck view. A condition is described, not evaluated by simulating a hypothetical scoring row. Unresolved mass/provider data remains unavailable with a reason, never fabricated zero. Avoid duplicate weight/bonus lines if a provider already supplies them.

## Gameplay Status

Show the current round and stage, current stage score and target score using their authoritative owner descriptors. List **installed** modifiers/passives in rack order, preserving separate instances, with name and complete effect/condition description. Include current instance counters/uses or configuration that changes the description and provisional warnings through the existing inspection capability. This includes actual installed rack items that supply the appropriate public descriptor, not every catalogue item or a parallel hard-coded list. Empty rack is a clear empty state.

Other HUD fields may remain in their existing HUD; this initial screen does not invent a new stats/history system, editable modifiers or future tabs. It is read-only: no buying, selling, rearranging, rerolling, changing counters or activation through these descriptions. Existing deck/material hidden-information constraints still apply. A no-active-run entry is unavailable or explains that there is no current run through normal availability configuration; it must not dereference an absent game.

## Host, providers and lifecycle

A shared tabbed status host accepts configured tab references, labels/order, initial selection, content/inspection providers and close action. Each registered tab provider supplies its captured plain-data content plus a scoped invalidation/subscription adapter for its owning state. Generic host code dispatches tab registrations and does not switch on tab names, card kinds or scene identity. The Deck provider owns inventory projection; Gameplay Status owns run/rack projection through narrow read-only sources. Do not teach the generic tab renderer the GameRun structure.

The scene composes the status host through its trait, retains the current deck-entry navigation handle for compatibility, and preserves the existing push/pop, Escape and `pausesBelow` policy. The bottom-right deck counter opens it; default first tab is Deck, with selection retained only within that showing. Back/close returns to the invoker with focus restored. Tab selection is local UI state, not a game save change. Keyboard tablist semantics, arrow/Home/End focus and Enter/Space activation follow the shared controls; touch targets remain usable and a long inspection string can scroll without hiding close. This tabbed information panel is not a menu-block enclosure: standalone Back/action blocks stay outside any readable information surface under #1364's contract.

Read owner state on entry and invalidate from the committed run/state owner if it changes while the overlay is open; redraw current inspection if its instance changed or was removed. No polling or per-frame rescoring. Reuse the committed channel for committed actions; any missing general state invalidation is an explicit narrow owner publication capability for state changes, not state diffing in a service or an assumption that `onCommitted` covers every settings/debug mutation. Re-entry always refreshes. Exit/cover disposes or suspends subscriptions, removes owned DOM/inspection regions and prevents stale callbacks updating a later showing. Opening/closing/selecting tabs uses existing UI sound conventions once through the input/action owner.

A new inventory list in saved state would diverge from authoritative zones. An enlarged hover tooltip alone would not expose requested material labels or gameplay tab. These findings establish source seams, not tested accessibility or browser behavior of the new screen.
