# Clone and reset facets (#580)

Documentation-only target. The owner explicitly rejected redundant research for this straightforward capability. Evidence: existing `stage-end.ts`/`round-end.ts` handler registries, cooking/material state reset modules, `modifier-registers.ts`, `card-states.ts` save adapters and `cards.ts` constructors already separate definitions from instance state, but there is no general exact-clone/reset facet. Reuse registered handlers; do not use `structuredClone` on runtime traits, functions, listeners or meshes. Coordinate [ownership](ordered-card-ownership.md), [opaque actives](opaque-actives.md) and `game-events.md` transactions.

## Resolved definition and facets

Every relevant block definition resolves exactly one retention policy (`stage`, `round`, `run`) and one reset facet: `resettable` with an ordered recipe/boundary configuration, or `nonResettable` with explicit refusal. A single optional declared parent supplies plain inherited configuration; local declarations override complete facet values. Resolve once at registry validation, reject cycles/missing parent/unresolved lifetime/contradictory facet declarations. Generic consumers request the facet operation through its registry, never inspect presence as a flag or branch on family/material. This is configuration composition, not class hierarchy or a side table keyed by kind.

Each serializable component registers clone and reset behavior/configuration where applicable. Clone codecs copy instance values and rebind registered capabilities; immutable definition/resources remain shared by reference/handle. Reset recipes select registered state handlers, not generic reflection over property names. Baseline is the resolved definition's configured state plus explicitly retained instance fields. A transform/reversion recipe names a target definition/state through validated configuration. No reset implicitly calls a creation generator or consumes RNG.

## Exact cloning (#581)

`clonable.clone(context)` returns an **unplaced** new logical instance in the same current state, with fresh IDs allocated by the transaction's allocator. Copy rank/suit/material, mutable component state, uses/current counters, modifier registers, retention/reset configuration and hidden payload contents exactly; recursively copy owned payload descriptors with fresh IDs and independent mutable arrays/maps. Shared definitions/assets stay shared. Clone does not copy zone/cell, historical reward receipts, subscriptions, timers, renderer resources or active presentation handles. No automatic placement, inventory adoption, cost, reward or mechanic is implied.

Validate the entire clone plan/required codecs first; allocate/construct within a transaction. On failure release any constructed resources and roll back ID allocation, state and RNG; the source remains unchanged. An unsupported component rejects explicitly rather than dropping state. Return new ID mappings for owned references so internal links refer to the clone subtree, not the source. Referential links to external live objects require a registered clone policy; never blindly rewrite opaque strings. A caller's adoption command validates a destination separately and commits together if it needs atomic clone-and-place.

## Reset and reset-clone (#582–#584)

`resettable.requestReset(context)` produces a registered command plan/result for the configured cause/boundary and baseline recipe; lifecycle integration requests the operation rather than naming fields/materials itself. The normal reset preserves instance identity, rank/suit and ownership unless an explicitly configured independent command says otherwise. `nonResettable` responds `unsupported` with a reason, through the same facet interface; absence/contradiction is a configuration error. It is not called immutable: other operations may still change the instance.

A reset-clone constructs an exact unplaced clone, then requests its reset facet in the same transaction. Unsupported reset or a failed recipe rejects the **entire operation** and frees the provisional clone, never falls back to ordinary clone. The source is never reset. Opaque stored payload defaults to preserve its fixed descriptor; a configured reset can restore wrapper-local counters without rerolling the hidden card. No player-facing clone item is created by this engineering work.

Acquired modifier lifetime clearing stays independent: resetting material/state does not clear all three registers. Recipes preserve run bonuses. Stage modifiers clear at stage boundary, round modifiers at round boundary, run modifiers at run end, through the registered lifetime handlers; an explicit reset recipe may clear a named temporary component only if documented/configured. Reset-clone preserves the source's modifiers unless its selected reset recipe explicitly includes that component, so it is not an undocumented way to remove permanent bonuses/penalties. Inspection describes current post-reset state.

## Boundary lifecycle (#504–#506)

Settle outgoing rewards before cleanup. Expire configured retention first; then request reset on survivors, clear independently matching modifier lifetimes, transfer surviving cards to their owners and shuffle under `ordered-card-ownership.md`. Expiry is distinct from destruction/animation unmount and never runs bomb transfers. Current examples are resolved declarations: ordinary deck cards and cooked meats retain for run; cooked meats reset to raw at stage end; Cloud retains only stage and never joins the run deck; Gelato retains run and reverts to Custard at round end. Derived meat states inherit their parent rules unless overridden. Limited-use item depletion remains its own consumption command; lifetime inheritance does not grant/refill uses.

A reset configured for a boundary must resolve to an executable resettable recipe. Explicit no-reset resolves to nonResettable and is not scheduled automatically. An explicit caller may still request it and receive the refusal. Restoration validates/loads saved state without triggering boundaries, resets, RNG, sounds or rewards. Use existing component persistence adapters; a new field/codec documents its exact compatibility under the current save policy before bytes change. Test another registered reset behavior without changing the lifecycle runner, inherited/overridden/none declarations, failure rollback, source/clone independence, permanent-bonus preservation and stage/round exactly-once boundaries.
