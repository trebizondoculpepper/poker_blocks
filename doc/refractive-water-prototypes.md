## Shared composable appearance

Reuse the fake-refraction assembly with independently configured **lookup distortion** and **rising bubbles** capabilities. Definitions/presets bring registered handlers and serializable settings. No generic renderer, room, frame loop or bubble runner branches on a backend/material/room identity or checks a trait as a flag. Shared code dispatches registered update/pass handlers. Any required generic hook is introduced as a reusable capability; no water-only timing path in Dev 17.

Both water presets preserve the cube geometry, clean faces, silhouette and separately readable artwork. Start with a slight cool water tint, restrained reflection and little or no spectral colour split; water must not inherit crystal rainbow defaults accidentally. Calm water omits bubbles; bubbling water composes the same optics plus the bubble capability. Do not duplicate the refraction shader for each prototype. Existing crystal and other presets retain their own settings when water controls change; configuration/uniform state is scoped to a preset/appearance instance while immutable textures, programs and compatible capture resources remain shared within a renderer.

### Subtle cyclic distortion

The distortion modifies the refraction **lookup offset**, never vertices or the cube outline. Add a very low-amplitude, spatially smooth perturbation to the existing view-dependent bend. Two slow waves with integer-multiple frequencies can loop seamlessly over a configurable period; provisional default **10 seconds**, tunable over roughly 8–12 seconds for the initial audition. Phases/amplitudes vary spatially so the background gently shifts rather than the whole cube merely zooming in and out. No fine normal grain, sub-facet pattern, new geometry, per-frame random noise or visible surface slosh.

Use a presentation clock passed through the registered update/frame capability, with period/amplitude/spatial-scale settings and stable cosmetic phase seeds. Derive from elapsed time rather than frame count; regular and irregular frame rates must not alter the cycle. Clock input and deterministic seed are independent of gameplay RNG. Reduced motion freezes distortion at a stable phase; re-entering/changing backend must not create uncontrolled uniform jumps or carry another preset's live settings. A zero amplitude reproduces the static baseline. Parameter magnitudes are bounded so grazing views cannot generate unbounded offsets or UV sampling artifacts.

### Bubbles without a shell

Reuse the pooled rising-bubble behavior through a published refractive-volume capability. The initial volume is the full block interior: it supplies wet membership, bounds and a world-up exit surface even though no outer container shell is drawn. Update this spatial contract from the block pose; particles remain inside the cube and rise toward world up as it turns. Prefer an adapter/provider satisfying the existing liquid-surface requirements over a second copy of bubble physics. If a reusable boundary hook is absent, implement/document that hook rather than testing material identity.

Expose count/density, size, rise speed, wobble, rest/emission interval, colour and opacity, independent of ripple strength/period. Use a fixed pool and cosmetic randomness. Under reduced motion keep bubbles still as the existing behavior does. Calm water remains bubble-free by composition, not a generic `if water` branch.

The refraction host must explicitly composite interior particles with the captured background before the outer reflection/print, so they read as being **inside** the optical volume. The opaque front must not simply depth-occlude them, and disabling depth tests to paste them on top is not an acceptable substitute. Supply registered interior render/pass hooks and appropriate bounds/ownership/depth masks; the selected renderer receives resolved pass data rather than discovering a material. Do not capture arbitrary other blocks' particles into the wrong object's interior. Reuse compatible renderer-wide captures where safe; do not add a per-block full-scene capture or physical transmission to make bubbles work. If correct isolation requires a materially different capture architecture, return it as a design follow-up before silently expanding the experiment. Record the current shared-target overlap limitation and demonstrate separated and overlapping blocks.

## Copy settings: reusable preset snapshots

Dev 17 gains **Copy settings**, for the selected backend/preset across the whole gallery, including the new water presets. Export all effective configurable values, not only controls that changed: numeric sliders, choice controls such as spectral map pattern/frequency, ripple settings and bubble settings, including defaults required to reproduce the appearance. No per-frame phase, GPU texture, render target, callback or mutable uniform object is serialized.

Each backend registers a typed config schema with stable field keys/defaults/validation, a snapshot operation and an apply/create-from-config operation. Controls bind those schema fields; labels are presentation text, never persistence keys. Snapshot/apply dispatch through the backend registry with no backend-ID switch in the copy button. Current/legacy backends with no exposed controls still supply a valid minimal/default snapshot or clearly declare unsupported export, never silently return an incomplete preset. New and tunable existing backends must support complete export.

The clipboard is formatted JSON: `{ schemaVersion: 1, backend: "<registered handle>", config: { ...effective values... } }`. The backend handle selects its registered factory/schema; it is not a behavior branch. Shared spectral-map settings that affect the selected appearance are included under that schema, not omitted as “global state”. Applying the copied config through the registered factory in a fresh session reproduces its settings. Backend docs identify the actual configuration module/field and show how to paste the exported `config`; production use remains a separate decision. This ticket does not authorize writing source files or choosing production water optics from the browser. A generic interactive Paste/Import feature is not required; round-trip through the public config API is.

Keep seed/count/camera/lighting and tested revision as optional separate comparison metadata, not shader settings; copying effect configuration must not change the run deck or gameplay state. Copy on the user's button gesture, report success only after the clipboard write succeeds, and use the existing copy UI sound (or register a suitable placeholder if none exists). If clipboard permission/API is unavailable, show a selectable read-only JSON fallback; never lose the tuned values or claim they were copied. The action and fallback need accessible labels/focus and cleanup with the tool.
