# Scheduler terminal scope ownership (#1235)

The scheduler's bounded pending/active work must not leave every completed scope and its captured configuration strongly retained for a whole session (#1038). Preserve the existing late `status(handle)` and `observe(handle, listener)` semantics without making hosts guess when to dispose a generation. This changes resource ownership, not scheduling or player behavior.

## Active records and terminal handles

The scheduler strongly owns a scope record while it is pending, including its parent/children, active/pending events, captured fallback configuration and listeners. When it becomes terminal, finish its event/effect cleanup and all required child accounting once. Capture an immutable **terminal status only** (finished/cancelled/failed and bounded diagnostic text), keyed weakly by the opaque scope handle. Remove its full record from the strong active scope map and detach it from its parent after its terminal state has been accounted for. No terminal map value may reference the scope, parent, handle, services, callbacks, payload or renderer resources.

An externally retained handle can therefore still retrieve its actual terminal status; an unreachable handle and its small status are collectible without a scheduler-owned archive or recent-status ring. `status` checks active records, then weak terminal status; an unknown handle retains the existing unknown-scope result. `observe` on a terminal handle invokes once immediately and returns a no-op unsubscribe. It does not store the new listener. Return an immutable status value or an independent copy so one observer cannot corrupt another's later answer.

Weak terminal storage has no enumeration or observable garbage-collection timing. Do not add tests that require a collector to run, rely on finalizers to dispose effects, or claim a fixed upper bound on handles external consumers intentionally retain. The guarantee is that scheduler-owned strong records/resources are bounded by unresolved work rather than all historical actions. A ring would cap history but silently change valid old-handle semantics; retaining full scopes in a WeakMap would still keep resource graphs alive when a lightweight status handle is retained. Only the status value belongs there.

## Settlement, cancellation and re-entry

Install the terminal status before notifying observers so a re-entrant `status`/`observe` sees the same terminal result. Notify the captured listener snapshot once; clear stored listeners and full configuration even if an observer throws. Preserve error reporting and parent-child ordering. A terminal child detaches only after the parent can account for it; the parent cannot settle before every child finishes cancellation. Re-entrant cancellation, observation, generation disposal or creation of new scopes must not double-decrement counts or dispose an effect twice. A local settlement routine may hold transient references until it returns, but not store them for future status reads.

`cancel` on an already terminal handle is a no-op. Scheduling/adopting a child under a terminal handle is rejected explicitly, never treated as a new root. Generation disposal cancels and releases all **active** roots and descendants once under existing re-entry guards; it does not erase truthful terminal statuses for externally retained handles. Pending handles become cancelled with their disposal status, while already finished/failed handles keep their original result. An unrelated foreign/unknown handle remains unknown. Observers creating work during disposal keep the existing born-cancelled behavior.

`counts.scopes` reports scheduler-owned unresolved scope records after cleanup, not terminal history. Diagnostic code must not iterate or preserve a parallel terminal collection. Existing event/effect/heap cleanup remains mandatory; weak status storage does not excuse retaining payloads elsewhere. Dispose-generation remains a real lifecycle operation, not the only fix for per-action retention.

## Evidence and verification

Source audit at `1a320fd`: `src/visual-events/scheduler.ts:createScope` adds records to `scopes`; `settleIfDone` and `completeCancel` notify without deletion/detachment. `disposeGeneration` is the only bulk clear. `status`/`observe` currently resolve from those records and return unknown when absent. Existing notification snapshots/clears listeners and protects parent bookkeeping from throwing observers. Preserve those guarantees while narrowing lifetime. This proposal does not claim a measured memory profile or a completed runtime cleanup.

Verify thousands of successful and cancelled nested actions return strong scope/event/effect counts to the appropriate baseline; retained old handles still report finished/cancelled/failed, including after generation disposal; terminal observation is immediate exactly once; status mutation is impossible/isolated; parent cancellation from child cleanup; observers throwing, cancelling/disposing, creating scopes or observing again; failed fallback and effect timeout; rejected schedule/child admission on terminal parents; old-generation late callbacks; and resource release with no retained config/listener callbacks in the strong graph. Tests inspect deterministic ownership/counters, not nondeterministic garbage collection. A long-session heap snapshot is useful additional evidence, not a substitute for these semantics.
