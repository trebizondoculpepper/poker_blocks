## Stock dancing and individual emphasis (#772)

Target for #774; no runtime changes in this documentation. Source audit at `5344a08`: `dance/dance-floor.ts:createDanceFloor/join/update` already provides registered beat cycles, shared phase/energy and reduced-motion behavior; `traits/interaction-feedback.ts:interactionFeedback` owns an inner hover/press transform. `shop-view.ts:DisplayedOffer/render/frame` writes the outer slot scale/rotation and owns arrival/drag/flight/return/burn mounts. `scene-behaviours.ts:shopStock` and `game-modes.ts` supply composition; `shop-view.css` supplies stable DOM placement/focus/hit areas. These support shared composition rather than a second analyser or per-offer-kind animations.

Compose a `shopOfferPresentation` controller trait with registered stock-target provider, dance cycle/shape references, amplitude/phase settings and interaction-feedback configuration. It joins every mounted offer to the **existing dance floor**, regardless of offer kind. Capture phase offset from stable stock order at mount (initially successive quarter-beat offsets), not from identity strings or gameplay RNG. Initial cycle is one bar; bob amplitude 0.03 of cube edge and tilt at most 4 degrees, configurable. No music yields zero energy; reduced motion rests. Muting alone does not stop an otherwise running shared beat clock: follow the existing beat provider, not a new audio-policy branch.

Separate transform ownership: layout root owns slot projection/base size; action-pose layer owns entrance/drag/return/purchase/burn; dance child owns bob/tilt; interaction-feedback child owns hover/focus/press emphasis; the visible model is their descendant. Refactor the old per-frame scale/rotation writer to its layout/action layer, not the inner layers. No two writers fight for one Object3D property. DOM hit targets remain fixed to the slot while small visual motion stays within its reserved extent, preserving prices, inspection text and neighboring targets.

Reuse a generic interaction-state provider subscribed through the real drag-source/pointer/focus owners; it emits normalized enabled/hovered/pressed state to feedback without attaching a menu-navigation action to purchasable stock. Default individual hover/focus scale is **1.04**, returning smoothly on leave/blur. For shop presentation, hover/focus emphasis may remain visible when purchase is unavailable, but availability still independently forbids the actual action and explains why. A shared configured feedback handler owns this policy; generic view/input code must not inspect offer kind or trait flags. Reduced motion uses the existing clear outline/focus/inspection cue without dancing or scaling animation.

At a motion hand-off, capture the currently displayed world pose into the action mount before resting inner layers, so hover/bob does not snap away. Return settles through the same pose-preserving ownership transfer. During active drag or finite arrival/return/purchase/burn movement, the action owner supplies a presentation envelope that rests dance/hover layers; do not discover this by diffing gameplay. Restore ambient participation after the item is resting, with the feedback's existing continuous response smoothing. Stock rebuild/sale/removal unregisters the old dancer and input subscription before disposing its mount. Cover pauses that scene's participation; resume joins once and reads current beat phase. Exit cancels owned feedback and releases subscriptions/material clones without disposing shared resources. Ambient dance/state-following springs remain frame behaviors, not one scheduled event per beat/particle.

Affordability, capacity, price, purchase, stock and drop outcomes are unchanged and model-first. Motion never gates input. Reuse `ui.hover` once per new pointer/focus hover action if not already owned by the input path; no per-beat sound spam or duplicate click/drop sound. `main.ts` only wires services. Verify every registered offer factory, unavailable offers, mouse/keyboard/touch, portrait/landscape, no music/mute/reduced motion, drag/reject/fly-back, repeated refresh/cover/resume/exit and no accumulated dancers.
